**New command: #branchmine**

`#branchmine <ore> [count] [y]`, for example `#branchmine diamond 8`. Digs down to the ore's usual y, then a tunnel the way you're looking, with a 32 block branch off both sides every 4 blocks. It only mines ore it can see from the tunnel. `#mine` works like before and `#gamer` doesn't use this (4c28b08)

The pattern and the idea come from `BranchMiningTask` in [Hackerokuz's AltoClef fork](https://github.com/Hackerokuz/altoclef/tree/LegitMineFeature), rewritten for 26.3

- A real world run got 3 diamonds in 14:50 at y -59, on a build one small fix older than this one
- A set-up stone box passes on this code: 6 diamonds in 2:47, and it stops its branches at gravel and lava like it should
- Not seen in a game yet: carrying on after the main tunnel gets blocked, the deep dark checks, tool trips, stopping after 3 bad sections, the 256 block limit, silk touch, golden picks
- The test of running another command right after it finishes didn't get that far, the test itself had a typo. The mine stopped fine

**Good to know**

- This is a nightly. Expect bugs
- `#gamer` is still being worked on and isn't reliable yet
- Known issue, not fixed: wither skeletons at fortresses. They got 4 deaths in the last 2 test games, and rods came slowly on those worlds

- A death in the End still costs a long rebuild. In one ocean test it never got going again and looped in its own tunnel until the cap
- If a run stops and says so, type `#gamer` and it picks back up
