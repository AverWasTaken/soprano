### What's new since v1.1.7-nightly.17

**#gamer: blocks that only look fine from far away**

- The bot can pick a block to mine from a chunk that isn't loaded yet, where every check says yes. Its own bed under an ocean was one: it picked the bed from about 1600 blocks away and walked there. Once the chunk loaded, the ocean rule said it can't mine there, so it stepped back out, the chunk unloaded, the bed looked fine again, and it went back and forth at the chunk edge for 25 minutes. Now a block picked that way that is still there once its chunk loads, but can't be mined, gets one ban that lasts through chunk reloads: 20 minutes (or until it has a better tool, when the block was only too slow to mine), or the whole run when the ocean rule is the reason. The log says which check said no (5268cda)
- In a test with a bed under a cold ocean picked from far away, the old code froze at the chunk edge, going back and forth 501 times until the 10 minute cap. The new code logged one ban naming the ocean rule and moved on. With the same bed on dry land, the new code still dug it out

**#gamer: dragon's breath at the pillar**

- Running from a breath cloud kept using the clouds from the first run. Each new run reused the old one, so the bot could run from a cloud that had already moved while the new one sat on top of it. Now each run uses the clouds that are there now and changes course when they change. Old test games showed this in 4 of the 6 End fights where the breath hit the bot two or more times before the dragon's first landing (3beea27)
- Paths stopped at the edge of a cloud and the bot stood there clicking at empty air for seconds. Now a cloud block costs extra to walk through, about as much as six blocks of walking, so the path goes around a cloud when it can and walks through when it has to. Places the bot avoids in a bastion or around a blaze spawner use the same rule, but there the ground was already off limits, so they act like before (3ae231c)
- After stepping out of a cloud, the bot walked straight back to its stand a block at a time, until a full size cloud finished it. Now while a cloud covers the stand, counting how big it will grow, the bot waits at the nearest spot clear of every cloud and skips a landing that comes in then. The next clear landing gets the beds (df39d93)
- In 8 test fights with clouds dropped on the stand, 4 on the new code and 4 on the old, the new code took 11 breath hits against 20, ran from breath 25 times against 89 and clicked at air next to a cloud 0 times against 61. Both killed the dragon in 3 of 4, and each died to the breath once. On the new code that death came from the first version of the test, which teleported a bot that was waiting clear of the clouds into a live one. That test was replaced for the last 2 fights on each side. The new code's fight without a kill died 4 times to endermen and the dragon up close, none of them to breath, and gave up after 10 minutes. The cost is 1 or 2 skipped landings in every fight on the new code. In one more test the new code didn't kill the dragon in 8 minutes: an enderman hit pulled the bot away in the middle of a landing, then it skipped 2 landings for real clouds on the stand

**Good to know**

- This is a nightly. Expect bugs
- `#gamer` is still being worked on and isn't reliable yet. 6 test games on the same worlds ran on this nightly's code before the dragon's breath fixes went in. 1 of 6 beat the game, in 130 minutes with 2 deaths, with a build running next to it for 25 minutes. That's worse than the 3 of 6 the last three nightlies' code won. All 6 games counted. One loss had other programs busy on the test machine for 12 of its 73 minutes, with no build seen
- The new ban is the only code change between those 6 games and the last 6, and it never fired in any of them, so the drop didn't come from it. One world that won last time died in the Nether, came back at its portal bed about 53 blocks under the surface with no tools and couldn't get back up. Another that won last time got to the last step before the End, filled its bag and stalled until it ran out of time. Fixes for both are being tested and aren't in this nightly. The other 3 never got past the Nether: 2 ran out of their 150 minutes, with 6 and 3 deaths, and 1 made no progress for 45 minutes, with 4 deaths
- No test games have run with the dragon's breath fixes yet
- The fix for running into wither skeletons down Nether corridors from the last notes isn't in this nightly either. Its tests couldn't tell the new code from the old, so it's on hold
- Nothing in this nightly changes how the mod loads
- If a run stops and says so, type `#gamer` and it picks back up
